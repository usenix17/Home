## HANDOFF -- operator runs these (needs admin pw; writes to production ipa9)

  --server=ipa9.starnix.net --domain=starnix.net --realm=STARNIX.NET \

  'sysrc freeipa_server_enable=YES dbus_enable=YES gssproxy_enable=YES; ipactl status'"

## Phase 5 attempt 1 -- FAILED (jail-side, production untouched)
- `ipa-client-install` died with:
  `FileNotFoundError: [Errno 2] No such file or directory:
  '/usr/local/etc/krb5.conf.d/freeipa'` (client.py configure_krb5_snippet ->
  shutil.copy to paths.KRB5_FREEIPA_DEFAULTS).
- **Root cause: FreeBSD-port bug** -- the port does not create
  `/usr/local/etc/krb5.conf.d/`, so the krb5 include snippet copy fails. This is
  local config, BEFORE any server enrolment -- `/etc/ipa` and
  `/etc/sssd/sssd.conf` were absent, so **ipa9 was NOT modified** (no rollback
  needed).
- Also: `sudo` was not installed in the jail (installer warns, non-fatal).
- **Fix applied (jail prep):** `mkdir -p /usr/local/etc/krb5.conf.d`
  (mode 755) and `pkg install -y sudo`. For codification, the role must create
  this dir before running ipa-client-install.
- Re-run the Phase 5 client-install fresh (no --uninstall needed).

## Phase 5 attempt 3 -- password OK, failed on SSL CA cert path (port bug)
- Ran WITHOUT `-U` (interactive prompt). **Password accepted**, CA cert retrieved
  from ipa9. Then: `Joining realm failed: JSON-RPC call failed: Problem with the
  SSL CA cert (path? access rights?)` (curl CURLE_SSL_CACERT_BADFILE).
- **Root cause: FreeBSD-port path mismatch.** Python framework
  `paths.IPA_CA_CRT = /usr/local/etc/ipa/ca.crt`, but the `ipa-join` C binary has
  baked-in Linux paths `/etc/ipa/ca.crt` and `/etc/ipa/default.conf` (port never
  patched them to LOCALBASE). `/etc/ipa` did not exist -> curl can't open the CA
  file.
- **Fix applied (jail prep):** `ln -s /usr/local/etc/ipa /etc/ipa` (covers all
  `/etc/ipa/...` refs: ca.crt + default.conf). For codification the role must
  create this symlink before enrolment.
- **Watch item:** `ldd /usr/local/sbin/ipa-join` shows MIXED krb5 linkage -- MIT
  `/usr/local/lib/libkrb5.so.3.3` AND base `/usr/lib/libgssapi_krb5.so.122`. May
  cause a GSSAPI failure in the next step; if so, that is why.
- Retry (interactive, symlink now in place):
  `ipa-client-install --server=ipa9.starnix.net --domain=starnix.net
  --realm=STARNIX.NET --principal=admin --no-ntp --force-join`

## Phase 5 attempt 4 -- ENROLLED, then failed on ccache (port bug)
- `/etc/ipa` symlink worked: **host ENROLLED in STARNIX.NET** (keytab has
  host/ipa10.starnix.net; ipa9 now has the host entry -- first production write).
  Created /etc/ipa/default.conf, sssd.conf, nsswitch. mixed krb5 linkage on
  ipa-join was NOT a problem.
- Then failed fetching the RPC `schema` from ipa9:
  `gssapi ... MissingCredentialsError -> ipalib.errors.NoCCacheError`.
- **Root cause: malformed `default_ccache_name = FILE`** (no path) in
  /usr/local/etc/krb5.conf -> resolves to a literal file `FILE:FILE` -> the
  schema RPC's GSSAPI finds no client creds in the default ccache. (Origin of the
  bare "FILE" is unclear -- client.py only writes KEYRING under
  is_persistent_keyring_supported(), which is False on FreeBSD; likely a port
  patch. Not chasing further.)
- Heimdal vs MIT: the INSTALLER uses MIT (`/usr/local/bin/kinit`, per log). But
  root PATH is `/usr/bin` before `/usr/local/bin`, so a BARE `kinit`/`klist` hits
  base Heimdal (reads nonexistent /etc/krb5.conf). Trap, but not the install
  failure cause.
- **Proven fix:** a concrete default ccache. With `KRB5CCNAME=FILE:/tmp/hostcc`,
  `/usr/local/bin/kinit -k host/ipa10.starnix.net` succeeds. MIT honors
  KRB5CCNAME over the broken krb5.conf value.
- **Retry action (operator, interactive):**
  `export KRB5CCNAME=FILE:/tmp/ipa_setup_cc` then re-run
  `ipa-client-install --server=ipa9.starnix.net --domain=starnix.net
  --realm=STARNIX.NET --principal=admin --no-ntp --force-join`.
  For codification: fix `default_ccache_name` to `FILE:/tmp/krb5cc_%{uid}` (or
  export KRB5CCNAME) for every ipa-*-install run.

## Phase 5 attempt 5 (KRB5CCNAME exported) -- same NoCCacheError
- Failure is in `api.finalize()` -> load_plugins -> remote schema fetch ->
  `ipalib/rpc.py get_auth_info` -> gssapi -> NoCCacheError (client.py:3217).
- Ruled OUT by isolated tests (all PASS on this jail):
  - `is_persistent_keyring_supported()` = False, so installer writes NO
    default_ccache_name (the bare `FILE` line is gone now).
  - `kinit_keytab(host, KRB5_KEYTAB, paths.IPA_DNS_CCACHE)` writes a valid host
    TGT to /usr/local/etc/ipa/.dns_ccache (klist confirms).
  - python-gssapi `Credentials(usage=initiate)` reads that ccache fine -- BARE or
    FILE:-prefixed, even with KRB5CCNAME set at RUNTIME and shell var unset.
  - Installer flow (client.py 3090-3217): admin ccache -> ipa-join -> KDESTROY ->
    kinit_keytab into CCACHE_FILE(.dns_ccache) -> os.environ[KRB5CCNAME]=CCACHE_FILE
    -> api.finalize schema fetch. Every isolated piece works; integration fails.
- Conclusion: subtle port bug in the enrollment RPC-auth ccache handling that
  isolated repro can't trigger. Next diagnostic: **KRB5_TRACE** on a real run to
  see exactly which ccache gssapi opens at the schema fetch.
- Retry with tracing (operator):
  `export KRB5_TRACE=/tmp/krb5trace.log; : > /tmp/krb5trace.log`
  then the same interactive `ipa-client-install ... --force-join`.

## KRB5_TRACE analysis (root cause of the ccache failure)
- Trace shows: admin AS-REQ -> admin TGT in /tmp/krbcc*/ccache; ldap/ipa9 via
  admin cache; host session-cookie config ops on .dns_ccache. **But NO
  `host/ipa10` AS-REQ** -- only one "Getting initial credentials" line, for
  admin. So the installer's host `kinit_keytab(host, KRB5_KEYTAB, CCACHE_FILE,
  config=krb_name)` (client.py:3150) does NOT actually obtain/store a host TGT in
  .dns_ccache during the real run, so api.finalize's schema RPC finds an empty
  default cache -> NoCCacheError.
- Yet the SAME kinit_keytab works when invoked by hand with the normal
  /usr/local/etc/krb5.conf. Difference is the `config=krb_name` temporary
  krb5.conf the installer passes. => genuine port bug in the enrollment host-TGT
  step; fixing it = patching the port's client.py + iterating (port dev, not a
  clean spike).
- State: host IS partially enrolled on ipa9 (host/ipa10 principal exists; first
  production write). Client install never completes.
- Port bugs found so far (all worth an upstream report to joneum@FreeBSD.org):
  1) missing /usr/local/etc/krb5.conf.d dir; 2) ipa-join baked /etc/ipa paths
  (needs /etc/ipa symlink); 3) cyrus-sasl2-gssapi + py-gssapi ship GSSAPI_BASE
  (need GSSAPI_MIT rebuild); 4) host kinit_keytab(config=temp) fails to populate
  the ccache the schema fetch reads.
